# 示例一：修完一个并发缺陷之后

## 任务

订单服务在高峰期偶发重复扣款，两周内 7 笔。日志被采样，复现不了。最后通过打开全量日志 + 构造并发压测复现，定位到重试逻辑没有幂等键。

## 交付说明（正文节选）

- 根因：支付回调重试时未携带幂等键，下游按“新请求”处理。
- 修复：回调入口生成 `idempotency_key = order_id + attempt_seq`，落库唯一索引兜底。
- 验证：并发 200 压测 30 分钟，重复率 0；补了 3 条回归用例。
- 遗留：历史 7 笔重复扣款需人工退款，已出清单。

## 收束

```
【收束】
原文：“调查就像‘十月怀胎’，解决问题就像‘一朝分娩’。”——《反对本本主义》（1930）
仿写：两周翻日志、两天复现，看着慢；可正是这两天，把“偶发”摁成了“必现”。【仿写】
鞭策：趁根因还热，把这条复现路径写成脚本进 CI——下次它再冒头，五分钟摁死。
```

## 为什么选这一条

- 这次任务的真正难点不是“写修复”，是“让它稳定复现”，对应“十月怀胎”的孕育期。
- 没用《实践论》“梨子的滋味”，是因为那句更适合“第一次动手”，而这次是“反复动手才看清”。
- 没用“下定决心”一类，因为这次不需要鼓劲，需要的是**把偶发变成必现**的方法论确认。

## 反例（不要这样写）

```
【收束】
正如毛主席所说：“世上无难事，只怕有心人。”这次故障的解决，充分体现了我们团队攻坚克难的强大战斗力！
```

问题：出处错误（“世上无难事，只怕有心人”是谚语，非毛原话）；无一字对应本次任务；“强大战斗力”是空话。
